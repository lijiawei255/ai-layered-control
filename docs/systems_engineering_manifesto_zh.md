# 工程系统论宣言：为什么"粗粒度分类 + 分层确定性控制"优于端到端大模型

> 本文是本仓库的论证长文。它回答一个问题：**在实时闭环控制里，把 AI 的权限放在哪一层，才既能拿到 AI 的能力，又不用赌上相位裕度、安全边界和现场可维护性？**
>
> 全文数字均来自仓库内公开脚本产生的**合成基准（synthetic benchmark）**：参数化合成非线性被控对象、固定故障时序、固定随机种子、纯 CPU、`dt = 1 ms`。**它们不是真实硬件、产线或临床测量结果**，用途是让论证可复现、可反驳，而不是代替实测。重跑命令见 [`AGENTS.md`](../AGENTS.md) 第 4 节，冷启动约 27 秒（其中 11.5 秒是 Simulink 首次加载的一次性开销）、预热会话约 10 秒。

## 0. 摘要

端到端连续策略（`u(t) = π_θ(x(t))`，把学习到的策略直接放进闭环、按控制频率逐拍推理）的问题不在于"AI 不够强"，而在于它把四件事**绑死**在了同一个模型里：语义判断、动力学反演、执行器权限、安全边界。四者绑定之后，任何一处的失败都会以最难排查的形式出现——不是报错，而是"看起来正常地在抖"或"在没见过的工况下自信地错"。

分层架构（见 [`README_zh.md`](../README_zh.md) 的架构图）把它们拆开：**10 Hz 的轻量分类器只判断"当前处于哪种工况语义"**，**1 kHz 的零依赖 C99 核心独占执行器**，**独立的物理残差探针**在分布外时显式弃权。这不是"把模型做小"的工程妥协，而是控制论上本来就该有的分工：**慢的、不确定的、需要解释的决定，交给慢环；快的、确定的、必须有界可审计的动作，交给快环。**

在工业参考预设的 40 s 四阶段基准上，这一分工得到的不是边际改善，而是数量级差异（详见第 4 节）：

| 维度 | 端到端连续策略 | 分层架构 |
| :--- | ---: | ---: |
| +35% 跨个体漂移下的 RMSE | 0.0516 rad | **0.0122 rad**（4.22 倍） |
| 边缘延迟抖动下的抖振指数 | 0.123 | **0.013**（9.50 倍） |
| 未见 OOD 故障下的安全包络越界（合成工况） | 1733 次 | **0 次**（弃权 2.0 ms） |
| 所需标定样本（部署达标） | ~120（仅名义机组；+35% 漂移部署下不达标） | **≤ 40** |
| 算力 / 内存 | 2.40e9 MAC/s / 5.60e6 B | **2.41e4 MAC/s / 2.21e3 B** |

## 1. 命题、反驳对象与判据

### 1.1 被批评的范式

传统 AI + 控制尝试多停在两条路上：一条是把 AI 当成**连续参数层的调参器**（对增益、阻尼做连续搜索与拟合），另一条是**端到端大模型直接拟合物理逆动力学**。两者都默认"结构不变，只把连续映射做得更准"。

本文批评的是第二种里**一种具体的部署方式**，而不是某个算法家族：

> 在生产闭环中，用一个连续策略直接产生执行器指令 `u(t)`，其推理频率等于或接近闭环频率（100 Hz–1 kHz），安全依赖训练时的软惩罚/奖励塑形，异常处理依赖策略"学会"。

它有三个必须同时成立的前提：

1. **数据覆盖充分**：训练分布覆盖部署时的一切工况（包括漂移、老化、未知扰动）；
2. **算力与延迟可控**：策略能在闭环频率下稳定推理，且推理延迟与抖动在相位预算之内；
3. **安全可由策略自身表达**：模型能学会"不要越界"，且这个"不要"在分布外依然生效。

这三个前提在实验室成立，在产线上极少同时成立。本文的论点就是：**这三个前提其实是三个独立的工程问题，应当用三套机制分别解决，而不是押在一个模型上**——也就是把问题从"连续参数层拟合"升级为"**离散结构层仲裁与未知拒识**"。

### 1.2 本文不主张什么

为了不让讨论变成稻草人，先把不主张的部分写清楚：

- **不主张**端到端学习没用。它在感知、任务规划、语义泛化上是目前唯一可行的路线；本仓库的慢环本身就可以是一个 VLA 模型，只要它输出的是**离散模态 + 置信度**而不是 `u(t)`。
- **不主张**"小模型天然比大模型安全"。安全性来自**结构**（独立的否决源、硬约束、可审计状态），不来自参数量。
- **不主张**传统 PID 已经够用。基准里固定 PID 支路（Branch 1）在四个阶段全面落后（S2 RMSE 0.1266、S3 0.1442、S4 0.1372），说明"什么都不学"同样不行。分层架构的收益来自**用 AI 做它擅长的事（分类），用确定性控制律做它擅长的事（调节）**，而不是回归人工整定。

### 1.3 三条判据

评价一个闭环 AI 架构，本文用三条可操作的判据，而不是离线测试集上的误差：

| 判据 | 具体问题 | 可判定的证据 |
| :--- | :--- | :--- |
| **可控性** | 抖动、漂移、延迟变化时，闭环还稳吗？ | 相位裕度/抖振指数/漂移扫描 RMSE |
| **可证性** | 能否证明"不会越界"，而不是"大概率不越界"？ | 越界采样点数、弃权延迟、故障审计位 |
| **可维护性** | 换机台/换患者时，改什么？谁改？多久改好？ | 现场整定旋钮数、是否需要重训、故障可归因性 |

这三条判据不是学术美学：现场工程师真正付钱买的是这三条。

### 1.4 与姊妹项目的关系：参数层与结构层

同一作者的另一仓库 [jev-tune](https://github.com/lijiawei255/jev-tune) 解决的是**单一控制器内部的连续参数层整定**：给定结构（例如 PID 或固定拓扑的调节器），如何快速、稳定地搜索增益/阻尼，并用 C99 安全边界兜底。本文所在仓库 `ai-layered-control` 则把问题上升到**离散系统结构层**：跨工况的粗粒度语义分类、极小样本收敛、算力与时间尺度解耦、OOD 显式拒识，以及把"谁拥有执行器"写进代码契约。

两者的分工是清楚的：**参数层回答"怎么调得又快又稳"，结构层回答"该不该换、换的依据是什么"**。本文的所有论证都只在结构层展开；参数层的具体搜索算法不是本文的主题。

## 2. 控制论论证

### 2.0 先说清楚：这套架构不是"新发明"

如果只把本文当成"又一个架构"，会低估它的分量，也会让移植变得随意。准确的说法是：**它把控制理论里几条成熟到可以写进教科书的结论，重新组合成了一串工程约束**。逐条对应关系如下：

| 本架构的构件 | 学术血统 | 本文加了什么 |
| :--- | :--- | :--- |
| 按模态切换一组预先设计好的控制器 | 监督切换控制（supervisory switching control）/ 增益调度（gain scheduling） | 把"谁来决定切换"交给一个**只能输出离散标签的 AI**，并给切换加驻留与恢复冷却 |
| 模态 + 连续动态 = 分段光滑系统 | 混合自动机（hybrid automata）/ 混杂系统 | 用**故障位掩码**把"当前处于哪个离散状态、为什么"变成可追溯日志 |
| 独立的安全监督器在越界时接管 | 运行时保证（runtime assurance）/ Simplex 架构 | 监督器的触发证据来自**物理残差**而不是策略自评 |
| 残差检测、解析冗余 | 故障检测与诊断（FDI）/ 解析冗余 | 残差只做**弃权触发**，不做故障定位（定位交给掩码与位号） |
| 状态约束下的安全 | 控制屏障函数（CBF）/ 安全集不变性 | 用"前视 60 ms 的软包络 + 粘滞硬否决"近似实现，成本极低 |
| 用积分吸收慢变模型误差 | 经典 PID / 内模原理 | 明确"积分只吸收**慢**误差，快的交给残差探针弃权" |

这张表的意义在于：**每一条都有几十年的验证历史，组合起来的行为是可预测的**；而端到端连续策略恰恰在"可预测性"这一项上最弱。本文不主张发明了新原理，主张的是**这些原理的重新组合，恰好是当下实时 AI 控制最缺的那一块**。

### 2.1 时间尺度分离：把"每拍都要决策"改成"偶尔决策、持续执行"

分层架构的第一个结构决定是**让两个环相差 100 倍**：外环 10 Hz（100 ms 一拍），内环 1 kHz（1 ms 一拍）。

为什么这个比例重要？因为它决定了"外环的每一次不确定性"在内环看来是什么：

- 外环抖动 60–120 ms，对 1 kHz 内环来说相当于**连续 60–120 拍不变**。内环只在"模态"这一个离散量上等待，不会在"指令值"上等待。
- 外环丢帧 15%，对内环来说等价于"这一段时间模态不变"。这是一个**定义良好的状态**，而不是一个故障：心跳看门狗（超时 300 ms）把它变成 `GATE_HOLD_LATENCY`，执行器保持。
- 反过来，如果策略必须每拍输出连续指令，那么任何一次推理抖动都会变成**前向通道上的延迟**，而不是"参数暂时不变"。

这就是奇异摄动/两时间尺度方法在控制上的经典结论：当快慢两个动态的带宽差足够大时，可以分别设计、分别验证，且慢环的扰动对快环的影响是**参数级**的而不是**信号级**的。端到端连续策略在 1 kHz 下运行，等于把这个分离条件人为抹掉。

### 2.2 相位与延迟裕度：120 ms 意味着什么

把数字算出来。工业预设的闭环目标带宽 `f_n = 3.0 Hz`，角频率 `ω_c = 2π × 3.0 ≈ 18.85 rad/s`。纯延迟 `τ` 在前向通道上贡献的相位滞后是 `φ = −ω_c·τ`：

| 延迟 τ | 相位滞后 | 在 3 Hz 带宽下的含义 |
| ---: | ---: | :--- |
| 1 ms（1 kHz 内环） | 0.019 rad ≈ **1.1°** | 可忽略 |
| 60 ms（S3 抖动下限） | 1.13 rad ≈ **64.8°** | 吃掉了典型 60° 相位裕度 |
| 120 ms（S3 抖动上限） | 2.26 rad ≈ **129.6°** | 裕度为负，闭环必然振荡 |
| 100 ms（外环周期，仅影响模态） | — | 不影响前向通道，因为模态是离散量 |

端到端支路在 S3 的失败不是"精度下降"，而是**相位预算被吃穿**：策略在 1 kHz 回路里，抖动直接变成延迟；再加上 15% 丢帧（保持旧值 = 额外延迟），闭环进入相位滞后型极限环。这个极限环在指标上表现为抖振指数从 0.013 升到 0.123——**9.50 倍**，且与"策略准不准"无关：即使策略在标称工况下完美，这个抖动也会发生。

分层架构并没有解决"推理抖动"，它做的是**让抖动不进入前向通道**：内环只消费离散模态，模态在 100 ms 内不变是完全可以接受的；真正需要每拍决定的是确定性控制律，而它根本不推理。这是"结构解决"而非"工程优化"的典型例子。

### 2.3 非平滑边界上的反演病态

控制里最难的不是"跟踪一条光滑曲线"，而是在**非光滑的物理边界**上保持稳定：摩擦的静/动切换、接触/脱离、齿轮间隙、执行器饱和。这些地方的真实映射 `u ↔ x` 在数学上是分段光滑甚至近似不连续的。

工业预设的 Stribeck 摩擦为

```text
F(v) = f_visc * v + f_c * tanh(v / v_eps) + (f_s - f_c) * exp(-|v| / v_s) * tanh(v / v_eps)
```

其中 `f_s = 0.45`、`f_c = 0.20 N*m`、`v_s = 0.02 rad/s`、`v_eps ≈ 4e-4 rad/s`。也就是说：

- 静摩擦到库仑摩擦的**主要跳变发生在一个 0.02 rad/s 宽的速度窗口**里；
- 该窗口内的等效斜率量级是 `(f_s − f_c)/v_s ≈ 12.5 N*m/(rad/s)`；
- 换向时速度会穿过零，**必然**经过这个窗口。

一个连续策略要在这里表现良好，必须在"速度接近 0"这一小段输入区域里复现近似阶跃的 `u`。而这一段恰好是传感器最不可靠的地方：位置噪声 `sigma = 0.0025 rad`，经过微分通道后的速度估计噪声与这个窗口同量级。于是**回归目标在最陡的区域被最噪的输入评估**——这是条件数问题（病态），不是训练技巧问题：再多的数据、再大的模型，也改变不了"输入噪声被斜率放大"这件事。

分层方案的处理方式完全不同：它**不去反演这条曲线**。

- 粗分类器只判断"是否处于非平滑边界段"（`REGIME_BOUNDARY_COMPLIANT`），这是一个**离散的、有间隔的**判断，不需要在窗口内做连续拟合；
- 具体的"力"由一组带积分作用的确定性控制律在边界段上"顶住"，误差由积分吸收，指令由斜率钳位限幅；
- 边界段的抖动由**驻留计时（150 ms）**抑制，而不是靠策略"学会不要抖"。

换句话说：**离散化本身就是一种正则化**。把连续反演问题换成离散分类 + 参数化控制，等于把一个病态的逆问题换成了一个良态的判决问题。这是分层架构在 S2（+35% 漂移 + 非平滑边界）取得 0.0122 vs 0.0516（4.22 倍）的结构性原因，而不是调参运气。

### 2.4 OOD 外推：软约束不是约束，置信度不是证据

分布外（OOD）故障——未见过的结构共振、传感器野值、电极阻抗突变——是端到端策略最危险的情形，原因很简单：**学习到的策略在任何输入上都给出一个有定义的输出，包括它从未见过的输入。** 软惩罚边界（奖励塑形）只在训练分布内塑造行为，对分布外没有约束力，也不会让策略"知道"自己在外推。

分层架构用两级机制解决这个问题，而且两级都是**结构性**的：

**第一级：独立证据。** 名义观测器（冻结的物理模型）给出预测残差 `r(t) = |y(t) − y_hat(t)|`。这个量与 AI 的权重无关：它是"测量与模型之差"。当残差超过阈值 1.0 时，系统显式弃权，进入 `REGIME_SAFE_FALLBACK`。

**关键区别**：AI 的置信度是**主张**（self-report），残差是**证据**（measurement）。一个幻觉的分类器可以非常自信，但残差不会因为它自信而变小。把两者都作为否决源，就把"AI 自我评估"这个不可靠环节从安全链里旁路掉了。

**第二级：硬边界。** 1 kHz 核心里有安全包络否决：`|x| > 0.9 × limit` 或 `|x| + 60 ms × |x_dot| > limit` 即强制回退。这是**硬约束**，与训练、与 AI 状态、与任务成功与否都无关，且带粘滞（sticky）与滞环（90% 触发 / 75% 清除），避免边界抖动。

两级机制叠加的效果是可测的：在本仓库的四阶段合成工况 S4 中，端到端支路越界 **1733 次**（最大 `|x| = 1.816 rad`，而硬包络是 1.0 rad），分层支路 **0 次**，弃权发生在故障注入后 **2.0 ms**（第 2 拍）。这个 2 ms 不是"AI 反应快"，而是"不需要 AI 反应"——残差探针在第 2 拍就越限了。

### 2.5 白盒可调试性：把"可解释"定义成可操作的东西

"可解释 AI"这个词在控制现场没什么用。现场工程师需要的是三件具体的事：

1. **可归因**：机器进了安全态，是什么导致的？——5 位粘滞故障掩码直接回答：心跳超时 / 残差越限 / 置信度不足 / 包络越界 / 帧损坏。一次 40 s 完整基准跑完后，掩码值为 `0b00011`（bit0 心跳超时 + bit1 OOD 残差），对应 S3 的丢帧与 S4 的寄生模态；包络位、置信度位、帧损坏位都未置位，与本仓库合成工况下"包络零越界、无坏帧"的记录互相印证。
2. **可局部修改**：某个工况表现不好，改哪个数？——4 个模态各 3 个增益，全部可读、可单点修改，且有 105 项回归测试保证不炸别的地方。
3. **可回归**：改完之后怎么确认没退化？——固定种子 + 四项工程检查 + 本节这些数字，改前改后对比即可。

端到端策略在这三件事上都只能用"重新训练 + 重跑测试集"来回答，而重训本身会带来灾难性遗忘——这就是"现场无法调"的真正含义。

## 3. 数据与算力的结构性论证

### 3.1 参数计数与样本复杂度

分层架构里 AI 究竟要学什么？本仓库的答案是：**3 个类原型 + 1 个归一化尺度表 = 16 个浮点数**。

- 输入：4 维**归一化无量纲**特征——`rms(e)/amp`、`rms(u)/u_max`、慢残差、`rms(x_dot)/v_scale`；
- 判据：到 3 个类原型的最小距离（最近类均值分类器），输出的是**3 档阻尼增益**；
- 置信度：`((d₂−d₁)/(d₂+d₁))·exp(−γ·d₁)`（边际 × 邻近度；γ 由标定得到），在类间边界与远离原型时同时塌陷——这正是需要弃权的地方。

端到端支路要学的是整条逆动力学流形。基准里给它一个"策略头"作为代表：4 变量、总次数 8 的完整单项式基，共 **495 项**；按常规现场做法，它**只用名义机组的数据训练**，然后分别部署在 0% 与 +35% 漂移的机组上。评分标准是"施加的阻尼与闭环最优阻尼偏差 ≤ 10%"（已施加 150 ms 驻留防抖），实测（N 为标定样本数）：

| N | 15 | 40 | 120 | 250 | 500 | 1000 | 2000 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 分层（+35% 漂移部署）[%] | 87.5 | 100 | 100 | 100 | 100 | 100 | 100 |
| 连续（0% 名义机组）[%] | 28.1 | 81.2 | 100 | 100 | 100 | 100 | 100 |
| 连续（+35% 漂移部署）[%] | 3.1 | 0 | 0 | 0 | 0 | 0 | 0 |

三个现象值得注意：

1. **分层方案在 N = 40 就饱和到 100%**。它的上限由"3 档离散化"这个设计选择决定，而不是数据量；再多的数据也不会更好，这正是"数据需求可事先算清"的来源。
2. **连续策略在名义机组上约 120 次标定即可达标**（N = 40 时 81.2%），说明它并非"永远学不会"；
3. **但同一套权重拿到 +35% 漂移的机组上，无论加到 2000 次标定都是 0%**。这解释了为什么"再多采点数据重训"在跨机台场景里往往是徒劳的——它缺的不是样本量，而是**部署工况与训练工况的一致性**。

> **样本量能改善的那个量，恰好不决定部署成败。** 决定成败的是学习器固定下来的支撑集有没有罩住部署点；而部署点由一次物理常数的整体偏移带到支撑集之外，与训练集的数据密度无关。

把两条曲线并排看，经验风险与部署风险的分叉是清楚的：N 从 15 → 40 → 120 → 2000，名义机组上的成功率是 28.1% → 81.2% → 100% → 100%，而同权重的部署成功率是 3.1% → 0% → 0% → 0%。前一条曲线随样本数单调改善、并在 120 次后饱和；后一条曲线从第一个点起就贴在地板上。二者是同一个学习器、同一组特征、同一条判据下测得的，唯一变化是部署工况。换言之，样本量确实在改善某个东西——它改善的是"在训练分布上的期望损失"，而这个量在部署分布上并不出现；一旦评价标准换成"漂移机组上的决策成功率"，"再多采一些数据"这个动作的有效性就立刻归零。

这个失败模式值得单独命名：**流形过拟合（manifold overfitting）**，它与通常所说的过拟合不是同一类误差。普通过拟合是围绕正确函数的方差问题——模型把噪声一起学了进去，更多数据、更强正则化、更小的假设空间都能把它压回去。流形过拟合是偏差问题：学习器把**支撑集**本身学错了，它贴合的是"这一台机器"的逆动力学流形，而这条流形在参数空间里只是真实族的一个切片。部署时物理常数整体平移（惯量 +35%、静摩擦 2.4 倍、Stribeck 速度 0.25 倍），工作点被移到支撑集之外，此时增加数据只会让这个切片的拟合更精确——它在错误的支撑集上更快地收敛，而不是朝正确的方向移动。加大模型容量、权重衰减、数据增强都不触及这一点，因为它们改变的是"拟合得多好"，而不是"在哪里拟合"。

结构性对策是把同一次映射拆成两段，而不是把它拟合得更准。定性段只要求把 4 维无量纲特征空间划成 3 个区域：12 个类均值坐标加 4 个特征尺度，共 16 个浮点数；特征按幅值、执行器上限与速度尺度归一化，常数整体平移在这个空间里几乎不移动工作点，划分因此可迁移。定量段干脆不学，交给一个有界权限的反馈回路：1 kHz 确定性 bank 的积分器吸收未知偏置，跟踪抗饱和防止换模态时释放能量，幅值与斜率钳位限住瞬态，三个现场旋钮留给工程师收尾。这里需要把话说完整：以上数据只来自**一条**合成漂移律（惯量、摩擦与 Stribeck 速度按固定比例整体偏移），它支撑的是"支撑集错配、而非样本密度不足"这个机理判断，不是一条普适的样本量定律；如果真实部署允许在漂移后的机组上采数，问题会退化成更便宜的那一个——目标机台需要多少次标定。在这个口径下，分层 40 次对连续 120 次依然成立：分层更省，但不是魔法。

这条曲线的工程意义在于：**它把"数据要多少才够"这个不可控问题，变成了"我的类边界在哪、需要多少标定样本达标"这个可以事先算清的工程量**。第 4 节的第 `[4]` 项检查就是按这个口径判定的：分层方案 `N ≤ 50` 时已达 95% 以上（实测 100%）；连续策略在名义机组上 `N = 40` 时 ≤ 90%（实测 81.2%）、`N = 120` 时 ≥ 95%（实测 100%）；而在 +35% 部署漂移下 `N = 2000` 时仍 ≤ 50%（实测 0%）。

### 3.2 算力与内存的量级差

解析估算（Panel C，模型内一致性估算，不是硬件 profile）：

| 项 | 端到端策略 @1 kHz | 10 Hz 分类器 + 1 kHz C99 核心 |
| :--- | ---: | ---: |
| 参数量 | 1.2e6 权重 | 16 个原型浮点 |
| MAC/s | **2.40e9** | **2.41e4**（分类器 120 + 核心 24000） |
| 内存 | **5.60e6 B**（4.8 MB 权重 + 0.8 MB 激活） | **2.21e3 B**（64 B 参数 + 96 B 状态 + 2 kB 代码） |
| 比值 | — | **99502 倍算力下降 / 2536 倍内存下降** |

这个量级差不是"优化出来的"，而是**频率差（100 倍）× 模型差（千倍）** 的乘积。它决定的不是"能不能跑"，而是"跑在哪里"：2.41e4 MAC/s 可以跑在 Cortex-M4F 的 1 ms 中断里，2.40e9 MAC/s 只能跑在带 NPU 的边缘 SoC 上，并且要和别的任务抢带宽——而抢带宽就意味着延迟抖动（见 2.2）。

## 4. 实验证据

所有数字来自同一脚本、同一被控对象、同一故障时序、固定随机种子。判据在脚本内预先写好，任何一条不成立脚本就抛错退出。

### 4.1 四项工程检查的证据链

**[1] `S2 drift robustness`（抗过拟合 / 免重训漂移鲁棒性）**：端到端支路 RMSE > 2 × 分层支路。
实测 **0.0516 vs 0.0122（4.22 倍）**。为什么是"结构性"而非"调参"：S2 注入的是 +35% 等效惯量、断屑摩擦 2.4 倍、Stribeck 速度 4 倍变陡，而端到端支路的逆模型冻结在标称对象上——它的误差是**系统性的模型误差**，不是随机噪声。分层支路的积分类控制律天然吸收常值/慢变模型误差，这就是为什么它能"不重训"。

**[2] `S3 latency decoupling`（延迟解耦）**：抖振指数 > 3 倍 且 RMSE > 2 倍。
实测 **0.123 vs 0.013（9.50 倍）**、**0.0933 vs 0.0125（7.46 倍）**。抖振指数的定义是"误差的 1 Hz 以上分量 RMS / 参考幅值"——它只惩罚高频抖动，不惩罚慢跟随误差，因此"更抖"不是"更慢"的同义词。端到端支路在 S3 的抖动来自相位预算被吃穿（2.2 节），分层支路的内环延迟恒为 1 拍。

**[3] `S4 OOD abstention and envelope safety`（OOD 弃权与包络安全）**：端到端越界 > 0、分层越界 = 0、弃权 < 10 ms。
实测 **1733 次 / 0 次 / 2.0 ms**（本仓库四阶段合成工况）。端到端支路的最大 `|x|` 达到 **1.816 rad**（硬包络 1.0 rad），且 **38.5%** 的 S4 采样点指令顶在 `±u_max` 饱和边界上——这不是"精度不足"，这是"在没见过的输入上强制外推"的直接后果。

**[4] `Data and compute efficiency`（数据/算力效率）**：分层 `N ≤ 50` ≥ 95%；连续策略名义机组 `N = 40` ≤ 90%、`N = 120` ≥ 95%；+35% 部署漂移 `N = 2000` ≤ 50%；算力下降 > 1000 倍。
实测 **100.0% / 81.2% / 100.0% / 0.0% / 99502 倍**。见 3.1 与 3.2 的完整曲线与解析估算。

### 4.2 一个诚实的小节：分层架构也有不占优的时候

任何基准如果只有"全赢"的结论，就值得怀疑。这里列出本基准里分层支路**不占优**的几处，以及它们为什么不改变结论：

| 观察 | 数字 | 解读 |
| :--- | :--- | :--- |
| S1 标称工况下的 RMSE | B3 0.0098 **略差于** B2 0.0087 | 标称工况正是端到端策略"背得最熟"的工况；分层方案把一部分精度换成了鲁棒性与可证性。这个差距是设计取舍，不是缺陷。 |
| S1 的抖振指数 | B3 0.010 **略高于** B2 0.007 | 分层支路的指令包含抗饱和积分与驻留切换，天然比"平滑拟合"多一点高频成分；但 S3 时二者的位置完全反转。 |
| S4 的 TV(u) | B3 148.3 **高于** B2 107.7 | **这是最重要的反例**：B2 的 TV 低，是因为它在 S4 有 38.5% 的时间把指令顶在 ±u_max 饱和边界上，钳位让差分变小。低 TV 在这里恰恰是失控的信号。评估执行器磨损必须同时看饱和占比与越界采样点数，不能只看 TV。 |
| S4 的"被解除武装"时间 | 8.96 s 停在 `REGIME_SAFE_FALLBACK` | 冷却机制让 AI 在故障持续期间长期不复位，代价是这段时间没有自适应能力。收益是包络零越界（本仓库合成工况）。这是保守取向，不是免费的。 |

跨领域复核也给出同样方向的证据（**均为合成动力学预设**，只比较同一预置内两支路的差异）：

| 预设 | S2 RMSE B2 | S2 RMSE B3 | S3 RMSE B2 | S3 RMSE B3 | S4 越界 B2 | S4 越界 B3 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 工业 (rad) | 0.0516 | 0.0122 | 0.0933 | 0.0125 | 1733 | 0 |
| 边缘 VLA (rad) | 0.0353 | 0.0086 | 0.2887 | 0.0102 | 1637 | 0 |
| 神经调控 (归一化) | 0.0551 | 0.0269 | 0.0711 | 0.0238 | 182 | 0 |

三个预置里分层支路的 S2/S3 RMSE 都低一个量级；S4 越界采样点数在三域中端到端支路分别是 1733 / 1637 / 182 次，分层支路均为 0（本仓库合成工况下）。

### 4.3 为什么这些证据可信

- **判据先于结果**：四项工程检查写在 `run_all_benchmarks.m` 里，任何一条失败脚本抛错、非零退出；
- **确定性**：C 测试不含 `rand()`；MATLAB 侧全部固定种子——四阶段基准 `seed = 7`、效率/漂移研究 `seed = 17`，两者都写在函数默认值里；
- **可反驳**：第 6 节给出可证伪的预测，欢迎在别的对象上打脸；
- **口径透明**：RMSE、抖振指数、TV(u)、越界采样点数、弃权延迟的定义都写在代码里（见 [`README_zh.md`](../README_zh.md) 第 2 节的指标定义），不是事后挑的；
- **合成基准的边界**：所有数字来自一个二阶 + Stribeck 对象与解析估算的算力模型，没有硬件在环、没有实测 WCET、没有真实患者数据。**真实部署的验收必须在目标对象上重跑四项工程检查**（`AGENTS.md` 第 4 节）。

## 5. 诚实的适用边界

### 5.1 这套架构失效的四种情形

| 情形 | 为什么失效 | 需要什么 |
| :--- | :--- | :--- |
| 需要 >10 Hz 的连续策略更新 | 外环带宽是结构性的，靠调参解决不了 | 要么提高外环频率并重算相位预算，要么承认这是端到端策略的场子 |
| 主导非线性不是"慢变参数" | 残差探针的判据是"与名义模型之差"，若模型每拍都错，探针会持续误报/漏报 | 需要可标定的名义模型，或换用与模型无关的 anomaly 检测 |
| 安全无法用状态量表达 | 硬包络、残差阈值都要求可观测量 | 只能退化为"任务级监控 + 外部安全系统" |
| 完全没有物理模型 | 残差探针无定义，架构退化成"分类器 + 一堆 PID" | 先做系统辨识；否则老实上端到端 + 独立硬件保护 |

补充两条**工程性**的失效条件：

- **邮箱不可靠且不可观测**：如果拿不到"帧年龄"，心跳看门狗就无从实现，抖动会以不可观测的方式进入系统；
- **现场没有能力记录故障掩码**：那么"可归因"这条收益拿不到，架构退化成一个更复杂的 PID。

### 5.2 什么时候仍然应该选端到端模型

这不是客套，是工程判断。以下情形端到端更合适：

1. **数据极其充足且分布稳定**：有百万级真实轨迹、工况几乎不变、且能长期在线验证；
2. **算力与延迟完全可控**：推理跑在实时核上、延迟确定、抖动在相位预算内（例如专用推理加速器 + 硬实时调度）；
3. **安全由独立硬件层保证**：例如低层已有独立的安全 PLC / 看门狗，软件策略只做优化，越界由硬件切断；
4. **任务是感知密集、任务级语义主导**：例如抓取规划、语言指令跟随——这些本来就该由大模型做，只要它输出的是**目标/模态**而不是 `u(t)`；
5. **回报函数本身就包含安全**：某些仿真/离线优化场景，安全约束可以用硬约束规划表达，端到端是更紧的解法。

**一个关键的中间地带**：端到端模型做"任务规划 + 模态选择"，确定性核心做"执行 + 安全"。这其实就是本仓库的分层架构，只是把慢环换成一个真正的 VLA——**慢环换成多大的模型都不违反架构，前提是它的输出仍然是离散模态与置信度，而不是执行器指令。**

### 5.3 判据速查

把第 1.3 节的三条判据变成可操作的检查表：

| 问题 | 若答"是" | 若答"否" |
| :--- | :--- | :--- |
| 工况是否会漂移（机台/患者/负载/老化）？ | 必须有"冻结模型 + 少样本分类 + 现场旋钮" | 端到端可行 |
| 闭环频率会不会遇到抖动的算力平台？ | 必须做时间尺度分离 | 端到端可行 |
| 是否有必须被证明的安全边界？ | 必须有独立于 AI 的否决源与硬约束 | 端到端可行 |
| 现场工程师是否需要局部整定？ | 必须有可读参数与故障归因 | 端到端可行 |

只要有一项答"是"，分层架构就是更省事的选择；四项全"否"，端到端更省事。

### 5.4 合规与定位

本文的方法论可以借鉴嵌入式防御性编程原则（零动态内存分配、有界执行步数、输入异常清洗、故障位记录），为后续工程化提供代码结构参考；但本仓库代码**并非**经过功能安全或医疗法规认证的生产级固件。本文的所有实验都基于参数化合成非线性被控对象，不含任何真实患者临床数据或产线机台数据。在把任何结论用于真实工业设备、机器人或神经调控系统之前，必须针对具体对象开展 FMEA/STPA 等危害分析、硬件在环（HIL）测试，并取得相应行业安全/医疗法规认证。

## 6. 可证伪的预测

如果一个理论不能被反驳，它就不是工程理论。以下预测可以在你自己的平台上检验：

1. **延迟预测**：把端到端策略的推理延迟人为抬高到 60–120 ms，其抖振指数应显著上升（本基准里同一支路在无延迟的 S1 是 0.007、在带抖动与丢帧的 S3 是 0.123）；而分层支路的抖振应**基本不变**，因为抖动不在它的前向通道里。
2. **漂移预测**：冻结 AI、把对象参数漂移从 0 扫到 +50%，分层支路的闭环 RMSE 应基本持平（本基准 0.0111 → 0.0151），端到端应单调恶化（本基准 0.0101 → 0.0783）。
3. **OOD 预测**：只要残差探针与安全包络是**独立实现**的，S4 类故障下越界采样点数应为 0；若不为 0，优先检查包络的前视项（本仓库是 `|x| + 60 ms·|x_dot|`）是否被调得过于宽松，而不是先怀疑 AI。
4. **数据预测**：分层方案的动作准确率应随标定样本数**先到天花板**（本基准 N = 40 即 100%）；若它随 N 持续提升，说明特征或类别定义有问题（等价于任务没定义清楚）。而连续策略在**跨工况部署**下应出现"样本量救不回来"的平台（本基准恒为 0%）。
5. **可维护性预测**：把 `gain_scale` 调大 10%，稳态 `|u|` 应上升；`damping_scale` 调大应抑制换向抖动；`safety_margin_scale` 调小应更早触发包络（C 测试 stage 5 已逐项验证）。

## 7. 结论

1. **端到端连续策略的失败不是"AI 不够强"，而是"权限放错了层"。** 语义判断、动力学反演、执行器权限、安全边界是四个独立问题，绑在一个模型上就同时失去可证性、可维护性和相位裕度。
2. **分层架构的收益是结构性的，可以预测。** 时间尺度分离把抖动移出前向通道（S3 抖振 9.50 倍差），离散化把病态反演换成良态判决（S2 RMSE 4.22 倍差），独立残差探针把"主张"换成"证据"（S4 在合成工况下越界 1733 → 0）。
3. **数据与算力的收益是量级性的。** 16 个浮点原型 vs 495 项策略头，2.41e4 vs 2.40e9 MAC/s，2.21e3 vs 5.60e6 B——这些差距来自任务定义（分类 vs 回归）而不是实现技巧；而且分层方案在 40 次标定后即饱和，连续策略在跨工况部署下再多样本也无法达标。
4. **这套架构有明确的失效边界。** 需要 >10 Hz 连续适应、没有可标定名义模型、安全无法用状态量表达的情形，端到端（配合独立硬件保护）仍然是正确选择。
5. **最值得记住的一句话**：*不要让 AI 拥有执行器，让它拥有选项。* 慢环提供的是"选项 + 置信度 + 理由"，快环提供的是"确定、限幅、可审计的执行"；两者之间的接口越小（本仓库是 9 个字段的邮箱），系统就越容易验证、移植和工程化。

## 附录 A：指标定义与复现

| 指标 | 定义 | 备注 |
| :--- | :--- | :--- |
| RMSE | `sqrt(mean((x − r)^2))`，按阶段统计 | 参考轨迹为五次 S 曲线点对点运动 + 驻留 |
| 相位滞后抖振指数 | 误差经 ~1 Hz 一阶高通后的 RMS / 参考幅值 | 只惩罚高频抖动 |
| TV(u) | `sum(\|u_k − u_{k−1}\|)`，40 s 累加 | 执行器磨损的一阶代理 |
| 越界采样点数 | `count(\|x\| > 1.0 rad)` | 硬包络，不是软惩罚 |
| 弃权延迟 | 故障注入到首次 `gate ∈ {2,4}` 的拍数 × 1 ms | 判据 < 10 ms |
| 饱和占比 | `mean(\|u\| ≥ 0.999·u_max)` | 与 TV 联合解读 |
| 分层方案饱和点 | 逐 N 的部署成功率首次达到 100% 的样本数 | 本基准 N = 40 |

## 附录 B：术语表

| 术语 | 含义 |
| :--- | :--- |
| 慢环（outer loop） | 10 Hz 粗粒度分类器，只输出离散模态 + 置信度 |
| 快环（inner loop） | 1 kHz 确定性 C99 核心，独占执行器 |
| 模态（regime） | 4 个离散工作区间：标称 / 高负载阻尼 / 边界顺应 / 安全回退 |
| 弃权（abstain） | 显式进入安全回退并给出 gate 状态，而不是静默钳位 |
| 残差探针 | 名义观测器的预测误差 `\|y − y_hat\|`，与 AI 无关的 OOD 证据 |
| 驻留（dwell） | 正常模态切换的最小持稳时间，150 ms |
| 冷却（cooldown） | 故障清除后重新武装 AI 所需的连续干净时间，500 ms |
| 故障掩码 | 5 位粘滞位：心跳超时 / OOD 残差 / 低置信度 / 包络越界 / 帧损坏 |
| 现场三旋钮 | `gain_scale` / `damping_scale` / `safety_margin_scale` |
